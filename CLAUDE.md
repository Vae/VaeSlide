# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

VaeSlide / VaeScroll: a scrolling screensaver written in Python with PySide6. Images and videos from configured folders scroll horizontally across several parallax layers. The author is mainly a C++ developer who is learning Python, and also uses this project to see how far AI-assisted development can go. Planned features are listed in `README.md`.

## Running

There is no build step, linter config or app requirements file. Dependencies live in `.venv` (PySide6, numpy, Pillow, moviepy); `requirements-dev.txt` adds pytest.

Run from the repo root as a module, because every import is written as `from src.X import ...`:

```
.venv\Scripts\python -m src.VaeScroll            # --window is accepted; --speed <multiplier> overrides "global speed"
                                                 # --renderer opengl|raster overrides "renderer"; --frame-stats logs fps and paint time
```

## Tests

```
.venv\Scripts\python -m pytest                                  # whole suite, about 1 s
.venv\Scripts\python -m pytest tests/test_swapping.py           # one file
.venv\Scripts\python -m pytest -k "no_respawn_thrash"           # tests matching a name
```

Offscreen has no OpenGL, so GL tests (`tests/test_gl_transitions.py`, most of `tests/test_tile_shaders.py`, the GL widget test) skip unless run on the desktop platform: `$env:QT_QPA_PLATFORM='windows'; .venv\Scripts\python -m pytest`. They compare shader output pixel by pixel with the QPainter fallback. `tests/helpers.py` has `render_gl`/`GLCanvas`, `render_raster`, `pixels` and `mismatch` for this. Each `render_gl` call makes a new canvas, and with it a new GL context; to test anything cached across frames, call `grabFramebuffer()` repeatedly on one `GLCanvas`.

`pytest.ini` puts the repo root and `tests/` on the import path, and `tests/conftest.py` sets `QT_QPA_PLATFORM=offscreen`, so no window opens. The fixtures are:

- **`use_settings`** (autouse): every test gets isolated built-in defaults, never the real settings.json. Call `use_settings({...})` to override values. It also resets the `@section_config` caches.
- **`reset_video_count`** (autouse): zeroes `TileVideo.active_count`.
- **`tile_type("name")`**: registers a lightweight fake `Tile` type in `TILE_TYPES`. Its `allow`, `multiplier` and `start_ready` class attributes, plus each instance's `ready` and `swappable`, control selection, caps, loading and swapping. Every instance is recorded in `created`. Strip tests use it instead of real images or videos.
- **`qapp`**: the QApplication, needed by tests that paint (mazes, the widget).

`tests/helpers.py` has `meta(...)`, which builds a MetaTile, and `make_strip(...)`, which builds a HorizontalStrip with an explicit `StripConfig`. Swap tests replace `src.HorizontalStrip.time` with a fake clock (the strip passes `now` to the swapper), and they scroll by 0 so tile positions stay fixed.

## Behaviour

`main()` currently forces `fullscreen = False` for testing, so the app always runs windowed no matter what flags are passed. Any key, drag, or click on empty space quits. The mouse wheel changes the speed of the layer under the cursor: wheel up is faster and wheel down is slower. The step size is the `"wheel speed step"` setting (see also `"tile swap seconds"`, a `[min, max]` range; a max of 0 or less disables swapping), and slowing down past zero reverses the layer. Each change is logged, and changes aren't saved back to settings.json.

## Configuration files (repo root)

- `assets.json`: asset folders, read by `read_asset_sources()` in `src/AssetScanner.py` from the repo root. The format is `{"sources": [{"type": "image", "path": "C:/pics"}, ...]}`, where `type` is a key in `TILE_TYPES`. The older `image_paths` and `video_paths` lists are still read. Paths that start with `#` are disabled, and folders that don't exist are skipped with a warning.
- `settings.json`: user settings, loaded by `src/Settings.py`. Classes read them with `get_settings().get("key")`, which returns a shared instance that is loaded on first use. Each new key needs a default in `Settings.DEFAULTS` so that a missing or partial file still works. For numbers, use `get_number(key, cast)`, which falls back to the default when the value is invalid. For `[min, max]` ranges, use `get_range(key)`, which returns a `(min, max)` float tuple, accepts a single number as `[n, n]`, and swaps reversed bounds. Each module keeps its own settings in a nested dict, called a section, for example `"tile video": {"tile swap seconds": ...}`. Read a section with `get_settings().section("tile video")`, which supports the same `get`/`get_number`/`get_range`. Section defaults are nested in `DEFAULTS` and merged key by key, so the file only needs the keys it overrides. A module names its section in a `SETTINGS_SECTION` constant and reads it through one cached accessor that returns a frozen, validated dataclass, decorated with `@section_config` from `Settings.py`: `video_config()` in `TileVideo.py`, `maze_config()` in `TileMaze.py`, and `strip_config()` in `HorizontalStrip.py` for the top-level `"tile gap"`, `"tile swap seconds"` and `"tile swap edge margin"`. `reset_config_caches()` clears them all. The current keys are `"renderer"` (`"opengl"` or `"raster"`, which turns every GPU effect off), `"opengl samples"`, `"tile shaders"` (see Tile shaders below), `"archive on middle click"`, `"archive directory"`, `"global speed"` (a multiplier on every layer's speed), `"tile gap"` (px; negative means tiles overlap) and `"layers"`. Archiving is skipped when no archive directory is set. `"layers"` lists the parallax layers back to front as `{"speed": <px/frame>, "overlap": <fraction of screen height>}`. `parse_layer_configs` in `ScrollLayer.py` skips invalid entries, and if no valid layer is left, the defaults are used.
- `.media_cache.json`: a generated, gitignored cache of `abs_path -> [w, h]` so startup doesn't have to open every file.
- Next to an image, an optional `<name>.json` sidecar can supply `weight`, `width` and `height`. When there is no sidecar, the dimensions come from MediaCache, or from Pillow on a cache miss.
- `crash.log`: `faulthandler` output, appended on every run. It is set up by `src/Diagnostics.py` `install()`, which `main()` calls together with logging, the excepthooks and the Qt message handler. Importing modules has no side effects.

## Architecture

The pieces, from the outside in:

- **The widget** (`src/VaeScroll.py`): the top-level widget and the entry point. Its behaviour lives in `ScrollWidgetMixin`, which has two subclasses: `EndlessScrollWidget` (a plain QWidget, the `"raster"` renderer, painting in `paintEvent`) and `GLEndlessScrollWidget` (a `QOpenGLWidget`, the `"opengl"` renderer, painting in `paintGL` with `"opengl samples"` MSAA). Both call the same `_paint_scene()`, so every tile and transition draws with QPainter either way. In the OpenGL one, raw GL such as shaders can go between `painter.beginNativePainting()`/`endNativePainting()`. `create_widget()` picks one from the `"renderer"` setting and falls back to raster when `opengl_available()` is False, which is always the case under the tests' offscreen platform. GL-only tests must call `pytest.skip` when no context is available. Animation is time-based: `_advance()` asks a `FrameClock` (`src/FrameClock.py`) how long the frame will be shown, then `_tick(frames)` calls `layer.tick(speed_scale, frames)` on every layer, in reference frames of 1/60 s (`REFERENCE_FPS`), and repaints. Layer speeds are therefore px per 1/60 s at any refresh rate. Tests call `_tick()` directly for exactly one frame per call. What drives `_advance()` depends on the renderer. The OpenGL widget runs one frame per display refresh off `frameSwapped` (swap interval 1), with `_timer` only as a 100 ms watchdog for when no frames are presented. Its clock snaps: every frame advances exactly one refresh period, and real time is kept only as a leaky `lag` that adds a catch-up step after a genuinely dropped frame. Don't use raw swap timestamps for motion: the Windows compositor returns swaps unevenly (e.g. 26 ms then 7 ms), and that noise shows up as jitter. The fixed 16 ms timer used before beat against the 16.7 ms refresh and put two steps into one refresh about once a second. Raster uses `_timer` as a precise timer at the refresh rate, with raw measured time, because it isn't vsynced. `--frame-stats` also reports the longest frame interval and the late (multi-period) frames. The layers are built from the `"layers"` entry in settings.json. `load_assets(type, path)` runs that type's `SCANNER`, and `load_procedural_assets()` adds the types that need no folder, such as mazes. Both add to a master `List[MetaTile]`, and `build_layers()` passes that list to every layer. Every layer shares one `TileContext`. `_layout_layers()` stacks the layers vertically, using each layer's `overlap` fraction of screen height. Clicks are hit-tested from the front layer to the back: left-click logs `tile.describe()`, which is the file path by default (`TileMaze` adds its algorithm, size, endpoints and phase), and middle-click moves the file into the `"archive directory"` folder.
- **`ScrollLayer`** (`src/ScrollLayer.py`): one parallax band. It holds a `LayerConfig(speed, overlap)` and a mutable runtime `speed` that starts at `config.speed`, a y offset, and a `HorizontalStrip`. When drawing, it translates the painter by its y offset and adjusts y for hit tests.
- **`HorizontalStrip`** (`src/HorizontalStrip.py`): one endless horizontal strip. It only handles placement and delegates the other two jobs to its `picker` and `swapper`. `_tiles` is kept sorted by x. `cull_and_fill()` works in both scroll directions. The direction comes from the sign of the last `scroll(dx)`, and a negative dx moves tiles right. It calls `removed()` on tiles that are fully off screen, then fills both edges. Only the leading edge, where new tiles come in, is pre-filled with one strip-height of buffer beyond the screen. `_spawn_tile` asks `picker.pick()` for an asset and passes it to `_create_tile`, which calls `create_tile()` from `src/TileTypes.py`; that looks up `meta_tile.type` in `TILE_TYPES`. After each scroll it calls `tile.tick(now, visible)` on every tile, then `swapper.update(tiles, width, now)`. A tile whose asset failed to load is reported to `picker.disable()`.
- **`AssetPicker`** (`src/AssetPicker.py`): decides which asset comes next. Each strip has its own picker, so layers have independent odds. The `MetaTile`s are shared between strips and never modified: the picker keeps its own current weight for each one in a dict keyed by MetaTile (which hashes by identity, `eq=False`), and every `pick()` halves the picked asset's weight. `pick(candidates=None, replacing=None)` first drops candidates whose tile class reports `can_select(replacing)` as False, and returns None when nothing is left. `TileVideo` uses this to enforce `"tile video"` → `"max loaded videos"` (-1 means no limit). A video → video swap doesn't count the tile being replaced. Then each remaining asset's weight is multiplied by `selection_weight_multiplier()` from its tile class. `TileVideo` returns `"tile video"` → `"weight per loaded video"` raised to the power of `TileVideo.active_count`, the number of live video tiles across all strips; 1.0 means no effect. If every weight is 0 it picks uniformly. `alternatives(meta)` lists other assets with the exact same reduced aspect ratio (`aspect_key`) and a different file, and `disable(meta)` sets an asset's weight to 0.
- **`TileSwapper`** (`src/TileSwapper.py`): decides when an on-screen tile swaps to another asset. `update()` runs once per frame. When a tile has been at least partly on screen for its `swap_after` delay (drawn at random from the `"tile swap seconds"` `[min, max]` range by `start_clock` each time the tile's clock starts or restarts), and is fully on screen at least `"tile swap edge margin"` px from both edges, it is swapped in place for one of `picker.alternatives()`, so the tiles next to it don't move. If there's no alternative, the tile is kept. The range is per tile type, from `Tile.swap_seconds(default) -> (min, max)`; video tiles use `"tile video"` → `"tile swap seconds"` instead. `Tile.can_swap()` can also hold a swap back. `TileVideo` returns False until the video has played through once, which it detects from the looping position jumping back to the start, an `EndOfMedia` status, or a playback error. While a swap is held back the clock keeps running, so the swap happens right after the video finishes. Replacements wait in `swapper.pending` until they're ready, then go in through a transition; `cancel_all()` drops pending replacements on resize.
- **Transitions** (`src/Transitions.py`): how a swapped tile changes to its new asset. When `TileSwapper` puts a replacement in place, `Transitions.begin(new, old, now)` attaches an `ActiveTransition` to the new tile as `tile.transition`. The new tile takes the slot right away, and the old tile is kept alive and moved along with it (`old.x = new.x`). `HorizontalStrip` advances transitions each frame after the swapper and draws through `Transitions.draw_tile()`. When a transition ends it is cleared with `finish()`, which releases the old tile. Use `Transitions.release(tile)` instead of `tile.removed()` wherever the strip discards a tile, so a held old tile is released too; resize finishes every transition, and swapping a tile again mid-transition releases its first old tile. Transition types subclass `Transition` with a `NAME` and `draw(painter, old, new, progress)`, where progress goes 0→1 and both tiles share the rect from `tile_rect()`. They are registered in `TRANSITIONS`:
  - `FadeTransition` (`"fade"`): the new tile fades in.
  - `StarSwipeTransition` (`"star swipe"`): a growing, turning star clipped to the tile.
  - `ZoomTransition` (`"zoom"`): a dolly-through, where the old tile scales up while the new one scales down from a close-up and fades in.
  - `SpinTransition` (`"spin"`): a perspective card flip around the Y or X axis, picked at random per swap, built with `QTransform.rotate(angle, axis)` and shaded as it turns edge-on. The strip background shows behind the card.
  - `MaskTransition` (`"mask"`): a luma wipe, and the first `ShaderTransition`. On OpenGL the mask is uploaded once per swap as an `R32F` texture and a fragment shader blends the two tiles; each frame only `progress` changes. The QPainter fallback (`draw_fallback`) draws the new tile into an offscreen layer, cuts it out with a `Format_Alpha8` image using `CompositionMode_DestinationIn`, and puts it on top. Mask shapes are pluggable in `MASKS` as `(w, h, rng) -> float32 array`, where low values are revealed first: `noise` (float value noise, so there are no ties that would show up as raster lines), `linear`, `radial`, `clock` and `blinds`. `equalize()` turns any mask into ranks so the revealed area grows linearly with progress. Masks are computed at no more than `MAX_MASK_SIZE` (320 px on the long side) and scaled up smoothly, which keeps full-screen tiles to about 5 ms per frame.

  Settings are in the `"tile transition"` section and are read through `transition_config()`: `"type"` (`"random"` picks per swap, `"none"` disables), `"seconds"` (0 means swap instantly), `"star points"`, `"mask shape"` (`"random"` or a key of `MASKS`) and `"mask softness"` (the width of the soft edge, 0..1), and `"use shaders"` (false makes shader transitions always use their QPainter fallback).

  **Shader transitions:** `ShaderTransition` runs GLSL when the painter is on the OpenGL renderer (`GLSupport.is_gl_painter`) and `"use shaders"` is on, and calls `draw_fallback` otherwise. The fallback is also used if the shader fails to compile; the default fallback is a fade. A subclass's `FRAGMENT` defines `vec4 shade(vec2 uv)` returning a premultiplied colour, after `PREAMBLE`, which declares `old_tile`/`new_tile` (texture units 0 and 1, sampled with `tile_uv(uv)` because GL renders them upside down), `progress` and `size`. Extra textures come from `extra_textures(new)` (units 2..6; unit 7 is the clip mask), and their samplers and other uniforms are set in `set_uniforms(program, new, progress)` with `GLSupport.set_sampler`/`set_uniform`. Never use PySide's `setUniformValue` with plain numbers, because its overloads are ambiguous. `Transition.release()` is called by `Transitions.finish()` and frees per-swap resources. Transitions draw tiles with `tile.paint()`, never `tile.draw()`, so the tiles' shaders show during the transition too.

  **`GLSupport`** (`src/GLSupport.py`) holds the plumbing:
  - `PaintState.of(painter, rect)` captures the painter's device transform, opacity, clip (in device px) and target size before QPainter steps aside.
  - `native_painting(painter)` suspends QPainter for raw GL.
  - `shader_program(name, shade_source)` builds `FRAGMENT_HEADER` + source + `FRAGMENT_MAIN`, compiles once per context and caches the program; on failure it returns None and logs once. The per-context cache is keyed by the C++ context pointer (`shiboken6.getCppPointer`). Don't key it by `id()` of a PySide wrapper: the wrappers aren't stable, and that bug recompiled every shader on every draw. Uniform locations are cached too.
  - `draw_quad(gl, program, state, textures, set_uniforms)` binds the program and draws `state.rect` from `gl_VertexID` with a shared empty VAO, so there's no vertex buffer. The vertex shader applies the painter's full `QTransform` as a `mat3`, perspective-correct, so spin and zoom work. `FRAGMENT_MAIN` multiplies the output by the painter's opacity and by clip coverage: any clip path is drawn into a coverage mask texture first, with its size rounded up to `CLIP_GRANULARITY`. Output is blended premultiplied. So a shader quad behaves like normal QPainter drawing.
  - `TileTarget` is an offscreen FBO. `render(gl, draw_fn, rect, scale, key)` draws with a nested QPainter at device resolution (scale rounded up to 1/`SCALE_STEPS` so zooms don't reallocate every frame). A matching `key` skips the redraw. `bound(gl, size)` binds it for a shader pass. Targets nest through a bind stack, which is what lets a shaded tile run inside a shader transition. FBOs carry a depth/stencil attachment, because QPainter's GL engine fills paths with the stencil buffer; without it, every non-rectangle fills its bounding box.
  - `float_texture(array)` uploads a float array as a texture.
  - GL objects must only be deleted while the context is current. So owners hand them to `defer_delete()` and never just drop them, and `GLEndlessScrollWidget.paintGL` calls `collect_garbage()` first thing each frame.

  To add a transition, subclass `Transition` (or `ShaderTransition`), implement `draw` (or `FRAGMENT` plus `draw_fallback`), and add it to the `TRANSITIONS` tuple. In `draw`, use `painter.save()`/`restore()`, clip with `IntersectClip` (never replace the clip), and keep drawing inside `tile_rect(new)`. Tests in `tests/test_transitions.py` check every registered transition automatically: it must start fully old and end fully new, never draw outside the tile, and leave the painter as it found it.
- **Tile shaders** (`src/TileShaders.py`): GPU effects drawn over a tile, on the OpenGL renderer only; everywhere else the tile draws plainly.
  - **Assignment:** `HorizontalStrip._create_tile` calls `assign(tile)`, which rolls each enabled shader's `"chance"` and appends instances to `tile.shaders`. A tile can get several.
  - **Clocks:** the strip calls `tick(tile, now, centre_on_screen)` each frame, and `ActiveTransition.update` ticks the old tile, which has left the strip.
  - **Drawing:** `Tile.paint()` → `TileShaders.draw()`. With no active shaders, or no GL, it is just `tile.draw()`. Otherwise the tile is drawn into the first shader's `TileTarget` (skipped while `tile.content_key()` is unchanged), each shader renders into the next one's input, and the last pass draws with the painter's `PaintState`. So shaded tiles follow every transition's transform, opacity and clip.
  - **Release:** `Transitions._discard` calls `release(tile)` wherever a tile is discarded.
  - **`Tile.content_key()`:** returns a value that changes when `draw()`'s pixels change; None (the default) means redraw every frame. `TileImage` and `TileVideo` return their image's `cacheKey()`. `TileShaders.paint_key(tile)` is the same for `paint()`; it's None while a shader animates, and shader transitions use it for their tile textures.
  - **Writing a shader:** subclass `TileShader` with `NAME`, a config dataclass (must have `enabled` and `chance`) built by `read_config(section)`, and a `FRAGMENT` defining `vec4 shade(vec2 uv)` that reads `uniform sampler2D tile` (sample with `tile_uv`) and `size`. Override `tick`/`active`/`set_uniforms` as needed, and add the class to `TILE_SHADERS`. `active()` False skips the pass entirely.
  - **Shaders:**
    - `HueRotateShader` (`"hue rotate"`) turns colours about the grey axis (Rodrigues' formula) at `"degrees per second"`, with a random direction and start; at speed 0 it's a fixed random shift.
    - `WaterDropShader` (`"water drop"`) starts once the tile's centre is on screen and it's ready. Ring ripples spread from a random point for `"seconds"`, displacing (`"strength"`) and lighting the image, with `"wavelength"` as a fraction of the tile height. When it ends, its texture is freed.
  - **Settings:** `shaders_config()` reads `"tile shaders"`: `"enabled"` (master switch), then per shader `"enabled"`, `"chance"` and its own keys.
- **Tiles** (`src/Tile.py`): `MetaTile` is a dataclass describing an asset (type, source dimensions, paths, starting weight as a float). It's shared by every strip and never modified. `Tile` is a placed instance with an `x` and a height; its width is derived from the aspect ratio. Every subclass has the constructor `(meta_tile, x, h, ctx: TileContext)`, where `TileContext` carries shared services such as the `AssetLoader`. Each subclass also sets the class attributes `TYPE` (its `MetaTile.type` string) and `SCANNER` (its `AssetScanner` subclass). Subclasses override `draw`, `set_height` and `removed`:
  - `TileImage` asks the `AssetLoader` for its scaled image and draws it as a QPixmap. After a resize it draws the old pixmap stretched until the new one arrives. It has an optional numpy "white to transparent" mask, which runs on the worker thread and is disabled by default.
  - `TileMaze` (`src/TileMaze.py`) is procedural and has no file. `TileMazeScanner` (`NEEDS_PATH = False`) adds `"tile maze"` → `"count"` MetaTiles named `maze:N`. Their width and height encode the maze's aspect ratio, `(cols + wall) : (rows + wall)`. The tile steps a generator from `src/MazeGenerators.py`, which yields `visit`/`link`/`head` events, at `"speed"` steps per second, starting once the tile is first visible. The maze is drawn into a QImage block by block on a `(2·cols+1)×(2·rows+1)` grid of walls and cells. Each maze has random `start`/`end` cells, at least `(cols+rows)//2` apart, drawn as markers on top. When generation ends it can animate a BFS solution from start to end. The phases are `generate` → `solve` → `flash`, where the path blinks at `FLASH_HZ` for `"flash seconds"`, and then `done`. `can_swap()` stays False until the flash is over and `"hold seconds"` have passed since the maze completed. Colors are random per tile. Animated tiles get `Tile.tick(now, visible)`, which `HorizontalStrip.scroll` calls each frame.
  - `Tile3DPipes` (`src/Tile3DPipes.py`, type `"3d pipes"`) is procedural. 3D pipes grow cell by cell through an `[x, y, z]` grid on black, and the tile's aspect ratio is `x : y`.
    - Growth: a pipe goes straight, turns with `"turn chance"` or when blocked, and ends when stuck or at `_max_pipe_length()` (`fill · cells / pipes per cycle`). Spheres mark each pipe's start, turns and end. A cycle ends after `"pipes per cycle"` pipes or once `"fill"` of the grid is used. After `"hold seconds"` it clears and starts again with new colours (`"color mode"`: `"per pipe"` or `"per cycle"`) and a new random camera yaw and pitch.
    - Never swapped: `swap_seconds()` returns `(0, 0)` and `can_swap()` is False.
    - Rendering is software 3D with QPainter: a perspective projection, cylinders drawn as trapezoids with a lit cross-section `QLinearGradient`, and spheres as `QRadialGradient`. Segments overlap slightly (`SEGMENT_OVERLAP`) to hide antialiasing seams.
    - Depth order uses an incremental painter's algorithm. Primitives go into `SLAB_DEPTH` (half-cell) depth slabs, each cached as a transparent layer, and the final image stacks the layers far to near. A new primitive is painted straight onto its slab's layer unless a nearer item in that slab overlaps its screen bounding box (`_can_append`); only then is the slab redrawn in order. `test_incremental_render_matches_a_full_render` checks the shortcut is pixel-exact.
    - Cost: a step is about 0.4 ms at a 270 px tile (a full redraw of a finished picture is about 35 ms, e.g. after a resize). Memory is roughly one tile-sized ARGB image per occupied slab, about 10 MB at 270 px.
  - `TileVideo` gives each tile its own `QMediaPlayer` and `QVideoSink`, converts frames to a scaled QImage, and stops the player in `removed()`. Always call `removed()` when a tile is discarded, or the players leak.
- **Asset scanners** (`src/AssetScanner.py` holds the base class; each subclass lives next to its tile): `scan(media_cache, path) -> list[MetaTile]` builds a type's entries, and a missing folder returns `[]`. Images match `IMAGE_EXTENSIONS` and videos match `VIDEO_EXTENSIONS`. A sidecar without a usable width or height falls back to MediaCache or Pillow. Images and videos default to weight 10000. Video dimensions come from moviepy, and unreadable files are skipped.
- **`AssetLoader`** (`src/AssetLoader.py`): a `ThreadPoolExecutor` of `"asset loader threads"` workers named `asset_loader_N`. `request_scaled_image(path, height, callback)` returns immediately. The worker loads the image and scales it as a **QImage**, and the callback runs later on the GUI thread, inside `process_completed()`, which `_tick` calls first thing each frame. Never create a QPixmap on a worker thread; convert with `QPixmap.fromImage` inside the callback.
- **Async tiles:** a `TileImage` holds its slot in the layout right away, because its width comes from the MetaTile dimensions, but it draws nothing until its image arrives. `Tile.is_ready()` and `Tile.load_failed` report the state. A swap stays pending in `TileSwapper.pending` until the replacement is ready, so the slot never flashes blank. When an asset fails to load, that strip's picker sets its weight to 0.
- **`ImageCache`** (`src/ImageCache.py`): a thread-safe (locked) cache of full-resolution QImages keyed by path. Entries that haven't been accessed for 15 minutes are purged.
- **`MediaCache`**: persists asset dimensions to `.media_cache.json`.

To add a new kind of tile: subclass `Tile` with `TYPE` and `SCANNER` set, subclass `AssetScanner` (set `NEEDS_PATH = False` if the type needs no folder), and add the class to the tuple in `src/TileTypes.py`. A folder-based type is then loaded from any `assets.json` `"sources"` entry with that `type`. Give the tile its own settings section with a `@section_config` accessor. `TileMaze` is the simplest complete example.

## Notes

- Paths are normalized to forward slashes throughout the code.
